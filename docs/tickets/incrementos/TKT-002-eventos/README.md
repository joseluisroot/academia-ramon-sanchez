# TKT-002 — Gestión de eventos, primer corte
Implementa catálogo administrativo, creación/edición de borradores, alta de tipos, control transaccional de capacidad y estados, UTC, auditoría y cuatro tablas. Solo administrador institucional con tickets.access y events.manage. Se conserva /tickets como workspace y se añaden rutas explícitas /tickets/eventos; no se abre /app. No se habilitan aún operadores por evento: event_users y event_access_points son esquema preparatorio, sin interfaz ni permisos efectivos. Tampoco edición de tipos, emisión, venta ni validación. No abrir eventos reales hasta completar QA y reglas posteriores.
Pruebas: ejecutar migraciones en DB local respaldada, comprobar tablas, crear evento ficticio, agregar tipo, rechazar exceso de capacidad, editar borrador, abrir, verificar bloqueo de edición y transición inversa, acceso denegado a padre y operador, flag apagado, prelaunch /app bloqueado. Verificar audit_logs y pruebas unitarias. QA TKT-001 reportado por usuario: 2 tests, 23 assertions, OK; integración HTTP no demostrada por ese resultado. No se ejecutó PHP/MySQL desde GitHub.
