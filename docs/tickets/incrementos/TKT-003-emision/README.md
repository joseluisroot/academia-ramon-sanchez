# TKT-003.1 — Emisión
Tres tablas nuevas: ticket_batches, tickets, ticket_status_history. Solo institucional admin con tickets.access y tickets.issue. Evento OPEN, cuota por tipo, máximo 500 por lote; correlativos por evento, bloqueo FOR UPDATE de events compartido con EventService, transacción y auditoría. Reenvío con mismo request_id/actor/evento devuelve lote previo si tipo y cantidad coinciden. No hay borrado ni reutilización de cuotas. Estado CREATED no autoriza ingreso. Hashes SHA-256 hex; token de 32 bytes hex y manual Crockford-like 16 caracteres/80 bits; AES-256-GCM con nonce aleatorio, contexto autenticado evento/tipo/lote/serial, sobre versionado v1. Nunca mostrar ni loguear secretos. No hay endpoint de descifrado.
## Configuración privada
Generar una sola vez con php -r "echo bin2hex(random_bytes(32)), PHP_EOL;" y colocar en .env local ARS_TICKETS_KEY = valor. No compartir ni registrar en Git. Respaldar clave de forma segura e independiente de DB; pérdida de clave impide recuperar originales. No rotar sin migración de sobres; producción requiere clave distinta. OpenSSL requerido.
